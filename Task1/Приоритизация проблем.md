# Проблемы и их решения (MoSCoW)

### Must have
* Монолитная архитектура DWH - сейчас данные и логика локализованы в SQL Server, который очевидно не будет в будущем справляться  растущему объемами поступающих в хранилище данных. Соответственно предлагается согласно схеме выше на новую структуру в которой логика сбора, хранения данных и получения отчетов разнесены.

* Низкая скорость формирования отчетов - также согласно описанию, текущая систему уже не справляется с объемами данных. Переход на Data Lakehouse позволит решить эти проблемы.

* Низкие возможности по масштабированию системы - в настоящий момент добавление нового бизнеса потребует доработок на всех уровнях. Разделение на домены и стандартизация интерфейсов позволит упростить работу

### Should have

* Изоляция медицинских данных - внедрение управления методанными на основе Data Hub позволит лучше контролровать доступ и состав медицинских данные попадающих в хранилище.

* Настройка системы мониторинга и логирования для новой инфраструктуры - позволит контолировать нагрузку и работоспособность новой системы

### Could have

* Настройка системы управление доступом - После разделения на домены необходимо настроить систему управления доступом к данным. Т.к. в системе у нас есть как финансовые данные о компании, так и медицинские данные, которые должны быть защищены лучше.

* Настройка CI/CD процессов для развертывания Data Lakehouse, ETL процессов, изменения API для сбора данные и описаний в каталоге методанных
