# Разработка технологического радара и роадмапа изменений для поддержки бизнес-целей компании

### Технологический радара

Категории:

* Trial — «пробные» технологии или «технологии на подъёме», которые успешно работают и проверены на реальной проблеме, но у которых, возможно, выявлены ещё не все ограничения. 
* Asset — «оценочные» технологии, которые являются многообещающими и имеют явную потенциальную ценность для организации — те самые инвестиции. Они подходят для создания прототипов в целях выявления ограничений и возможностей.
* Adopt — устоявшиеся технологии. Они используются в проде, имеют низкий уровень риска и рекомендуются к широкому применению.
* Hold — по факту технологии, которые больше нежелательны для применения в новых проектах. Они с большой вероятностью будут постепенно выводиться из ландшафта.

| Технология / Подход | Категория | Описание |
|:-------------------:|:-------------:|:-----------------------------------------------------------------:|
| Apache Airflow | Asset | Движок оркестровки процессов обработки данных (ETL). Внедряется как часть нового хранилища Data Lakehouse |
| DataHub | Asset | Платформа с открытым исходным кодом для управления метаданными. Внедряется как часть нового хранилища Data Lakehouse |
| Dremio | Asset | Движок запросов для аналитики данных в озере данных и направлена на ускорение аналитических нагрузок и задач искусственного интеллекта. . Внедряется как часть нового хранилища Data Lakehouse |
| Data Lakehouse (S3 + Iceberg) | Asset | Это гибридное решение, которое сочетает в себе масштабируемость и гибкость озер данных с надежностью и функциями управления данными хранилищ данных. . Внедряется как часть нового хранилища Data Lakehouse |
| Apache Camel | Adopt | Достаточно популяроная современная система в области интеграционных платформ |
| Python | Adopt | Фактически является стандартом в области ИИ и аналитической обработки данных |
| Golang и Java | Adopt | Современные языки программирования, которые активно развиваются и обеспечивают реализацию всех современных подходов к разработке |
| Power BI | Adopt | Популярное решение от Microsoft для быстрого создание дашбордов и отчетов |
| Microsoft SQL-сервера 2008 | Hold | Устаревщая БД, необходимо запланировать отказ от нее как DWH и переход на более новую версию для оперативных систем |
| Power Builder | Hold | Устаревшая платформа для разработки интерфейсов. В настоящий момент ее поддерживают, но развития нет. Необходимо запланировать перевод на web-приложения на базе React или Vue |

# Описание шагов роадмапа

| Номер | Название шага | Описание обоснование |
|:--:|:--------------------------------:|:-----------------------------------------------------------------:|
| 1. | Формирование API для данных | Создание структуры данных для медицинских, финтех доменов и определения фиксируемых событий в доменах. Необходимая подготовительная работа, позволяющая дальше независимо реализовывать отправку данных из доменов и их обработку на стороне BI команды |
| 2. | Разработка/настройка выгрузки данных в Apache Camel | Реализация выгрузки необходимых данных в хранилище по опреденным ранее API |
| 3. | Настройка передачи метаданных в DataHub | Реализация системы каталогизации метаданных. Позволит отслеживать происхождение данных (lineage)  |
| 4. | Настройка Apache Camel | Необходимо вместе с определением API для данных настоить правила в Apache Camel для правильной передачи этих данных дальше |
| 5. | Настройка Data Lakehouse | Развертывание системы Data Lakehouse, настройка всех необходимых внутренних взаимодействий |
| 6. | Настройка DataHub | Развертывание системы каталогизации метаданных. Позволит отслеживать происхождение данных (lineage) |
| 7. | Построение ETL/ELK процессов | Разработка процессов очистки, трансформации и загрузки данных в Data Lakehouse. Без этого не будет наполнения данными хранилища |
| 8. | Настройка портала самообслуживания | На базе Dremio равертывается портал, позволяющих аналитикам получать прямой доступ к данным в хранилище. Что существенно урощает и ускоряет формирование кастомных отчетов и анализов |
| 9. | Построение необходмых отчетов / миграция старых отчетов в Power BI | Перенос стандартных очетов в новую архитектуру, что позволит уже полностью отказать от старой DWH |
